QualModel / LLM Survey Model Specification

A research pipeline that converts qualitative survey or interview text into a structured causal model with quote-level provenance and reproducibility artifacts.

Evidence-backedLocal-first HTMLSource inspected

The problem it solves

LLM-assisted qualitative synthesis can invent or overstate relationships. QualModel makes extracted variables, relationships, hypotheses, moderators, contradictions, and literature checks traceable back to source chunks and quotes.

Current features

  • CSV/TXT/PDF/DOCX parsing, cleaning, dedupe, chunking, metadata, and language detection
  • Persistent survey and literature vector stores with cached embeddings
  • PubMed/Semantic Scholar retrieval and topic-query construction
  • Typed per-chunk extraction with quote/chunk provenance
  • Cross-chunk gap detection, structural coverage, testability, and clarification planning
  • Bounded iterative refinement
  • Deterministic consolidation, contradiction detection, literature validation, and novelty flags
  • YAML, Mermaid, HTML, Markdown evidence, JSON, DOCX, cost, and run-log exports
  • Versioned prompt registry, deterministic fixture evaluation, bootstrap statistics, ablation runner, and Streamlit review surface

Main execution flow

  1. Parse supported files, normalize and deduplicate responses, then chunk and store them with metadata.
  2. Discover topics, retrieve literature, and populate a second vector store.
  3. For each survey chunk, retrieve dual context and request a typed extraction with variables, relationships, hypotheses, moderators, gaps, and evidence.
  4. Aggregate gaps, generate/route clarification questions, optionally auto-answer from literature, and re-extract until a threshold or iteration cap.
  5. Consolidate chunk models, detect/resolve contradictions, and validate hypotheses against literature.
  6. Write human-reviewable and machine-readable exports plus prompt/model/dependency/cost provenance.

Installation and run commands

Commands below are taken from the repository. Run them from the project root unless the first command changes directory.

git clone https://github.com/haseebraza715/QualModel.git
cd QualModel
make install
export OPENROUTER_API_KEY=sk-or-...
python3 main.py --input data/raw/synthetic_workplace_survey.csv
python3 scripts/smoke_offline.py
make reproduce
make eval
python3 -m streamlit run app.py
Local verification. Ran the offline smoke and deterministic evaluation tests with system Python: 2 passed in 0.25 seconds. Full live behavior requires the pinned environment and API credentials.

Known limitations and technical debt

  • Outputs are structured first drafts, not human qualitative coding or publication-ready evidence.
  • The gold set is small/synthetic, so current perfect recall has little headroom and broad validity is unknown.
  • Token/cost figures are estimates because the structured-output path does not retain provider usage metadata.
  • Non-English quality is unevaluated; PDF extraction degrades on scans, tables, and complex layouts.
  • Prompt sanitization is not a formal security guarantee.
  • Structural coverage is a schema-gap heuristic, not theoretical saturation or completeness.
  • No committed ablation artifact currently verifies quality/cost deltas.
  • Older NEXT_STEPS text says matcher/tests/prompts were weaker than current code; prompt sources still exist in both Python and registry forms.
